TaxiLink, c'est quoi au juste ?

Une explication super simple, comme si tu avais 10 ans.

Imagine que tu veux construire une cabane.

Tu peux la faire de deux manières différentes :

  • Soit une cabane dessinée sur une feuille que tu regardes à travers une fenêtre.
  • Soit une vraie cabane en bois dans laquelle tu peux entrer pour de vrai.

Eh bien dans TaxiLink, c'est pareil : il y a deux versions de l'app.

1) La PWA : la cabane derrière la fenêtre

PWA ça veut dire Progressive Web App (en français : « application web qui fait genre c'est une vraie app »).

C'est en fait un site internet, comme YouTube ou Wikipédia, mais qui a appris à se déguiser en application.

Comment ça marche ?

  • Tu ouvres ton navigateur (Chrome, Safari...) et tu vas sur l'adresse du site.
  • Tu peux ajouter un raccourci sur l'écran d'accueil de ton téléphone.
  • Hop, ça ressemble à une vraie app... mais derrière, c'est un site web.
Dans le projet TaxiLink, la PWA est rangée dans le dossier : apps/web

Avantages : pas besoin d'installer, ça marche partout (téléphone, ordi, tablette).

Inconvénients : ça doit passer par le navigateur, c'est moins puissant pour utiliser le GPS, l'appareil photo, ou marcher quand tu n'as pas Internet.

2) L'app Expo (l'app native) : la vraie cabane en bois

Native ça veut dire « vraie application installée sur le téléphone », comme Snapchat ou TikTok.

C'est une vraie app avec son icône sur l'écran d'accueil. Elle fonctionne même quand tu n'as pas Internet, elle peut utiliser le GPS, vibrer, envoyer des notifications, etc.

Et Expo dans tout ça ?

Expo, c'est une boîte à outils magique qui permet aux développeurs d'écrire une seule fois le code de l'app, et ensuite Expo fabrique tout seul la version Android et la version iPhone.

Sans Expo, il faudrait tout écrire deux fois (une fois pour Android, une fois pour iPhone) avec deux langages de programmation différents. Imagine devoir réécrire le même livre en français et en anglais en même temps : long et compliqué !

Dans le projet TaxiLink, l'app Expo est rangée dans le dossier : apps/mobile-driver-v2

Il existe aussi un ancien dossier apps/mobile-driver qui sert juste de référence (un brouillon qu'on garde pour s'en inspirer, comme un vieux dessin qu'on regarde pour faire le suivant).

PWA contre App native : la grande bagarre

PWA (le site déguisé)

  • Marche dans le navigateur
  • Pas besoin d'installer
  • Marche sur tous les appareils
  • Mais : pas top quand on n'a pas Internet
  • Mais : moins rapide

App native (la vraie app)

  • Installée comme un jeu
  • Icône sur l'écran d'accueil
  • Marche sans Internet
  • Peut utiliser GPS, appareil photo, notifications
  • Mais : il faut l'installer depuis un store

3) Comment s'appellent les fichiers d'app ?

Quand on fabrique une app native, ça donne un fichier. Et selon le téléphone, ce fichier n'a pas le même nom de famille.

Petite métaphore :

Imagine que tu veux offrir un jouet à un copain. Tu vas l'emballer dans une boîte. Eh ben le nom du fichier d'app, c'est juste le type de boîte qu'on a utilisé pour emballer le jouet.

ExtensionNom completC'est quoi ?
.apk Android Package La « boîte » pour Android. On peut l'installer direct sur un téléphone Android sans passer par le Play Store. Utile pour tester l'app entre potes.
.aab Android App Bundle La « super boîte » qu'on envoie à Google Play. Google ouvre la boîte et fabrique tout seul la bonne version pour chaque téléphone Android (qui n'ont pas tous la même taille d'écran, le même processeur, etc.).
.ipa iOS App Store Package La « boîte » pour iPhone et iPad. C'est ce qu'on envoie à Apple pour publier sur l'App Store.
.app Application Bundle La version pour le simulateur iPhone sur un ordi Mac. C'est juste pour tester pendant qu'on développe.

Tous ces fichiers, on les appelle ensemble des « binaires natifs » ou des « builds natifs ». Pas besoin de retenir, c'est juste le mot fancy qu'utilisent les grands.

Pour résumer (le TL;DR de papa)

  • PWA = un site web qui se fait passer pour une app, rangée dans apps/web
  • App Expo = la vraie app native (Android + iPhone), rangée dans apps/mobile-driver-v2
  • .apk = boîte Android pour tester / installer à la main
  • .aab = boîte Android pour Google Play
  • .ipa = boîte iPhone pour App Store
  • .app = boîte iPhone pour les tests sur ordi

Voilà, maintenant tu peux frimer dans la cour de récré.
