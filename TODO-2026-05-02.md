## 🔮 Pour plus tard — Mettre en place le workflow Supabase local pro

> **Pourquoi pas maintenant ?** L'environnement Windows actuel n'a pas la virtualisation hardware activée dans le BIOS, et l'user ne souhaite pas y toucher (légitime, c'est intimidant et risqué). Sans virtualisation, pas de WSL2, pas de Docker, pas de Supabase CLI local.
>
> **Quand le faire** : à un de ces 3 moments (le 1er qui arrive) :
> 1. **1er patron payant signe** → on ne peut plus se permettre de tester directement sur prod, l'investissement BIOS devient justifié
> 2. **Changement de PC** → si nouveau PC, vérifier dès le départ que la virt est activée (souvent par défaut sur les portables récents)
> 3. **Frustration sur le workflow actuel** → si copier-coller dans le SQL Editor devient pénible (plus de 3 migrations par mois)

### Ce qu'il faudra faire à ce moment-là

**Phase 1 — Activer la virtualisation BIOS** (~10 min, 1 fois dans la vie) :
- [ ] Identifier marque/modèle PC : `(Get-CimInstance Win32_ComputerSystem).Manufacturer + Model`
- [ ] Méthode propre : Démarrage avancé Windows → Dépannage → Options avancées → UEFI
- [ ] Dans BIOS : chercher "Virtualization Technology" / "Intel VT-x" / "AMD-V" / "SVM" → Enabled
- [ ] F10 Save & Exit
- [ ] Vérifier dans PowerShell : `(Get-CimInstance Win32_Processor).VirtualizationFirmwareEnabled` doit retourner `True`

**Phase 2 — Installer WSL2** (~5 min) :
- [ ] PowerShell admin : `wsl --install`
- [ ] Reboot
- [ ] Créer user/password Linux quand demandé
- [ ] Vérifier : `wsl --status` affiche `Version par défaut : 2`

**Phase 3 — Installer Docker Desktop** (~10 min) :
- [ ] Télécharger https://www.docker.com/products/docker-desktop/
- [ ] Installer en cochant "Use WSL 2 instead of Hyper-V"
- [ ] Redémarrer
- [ ] Lancer Docker Desktop, skip la connexion
- [ ] Attendre baleine 🐳 stable
- [ ] Vérifier : `docker --version` retourne `Docker version 27.x.x`

**Phase 4 — Installer Supabase CLI via Scoop** (~5 min) :
```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
irm get.scoop.sh | iex
scoop bucket add supabase https://github.com/supabase/scoop-bucket.git
scoop install supabase
```
Vérifier : `supabase --version` retourne `2.x.x`

**Phase 5 — Init du projet** (~10 min) :
- [ ] `supabase init` à la racine TaxiLink
- [ ] Déplacer `apps/web/supabase/migrations/` → `supabase/migrations/` à la racine
- [ ] `supabase login` puis `supabase link --project-ref ivumykufinlniffxqlud`
- [ ] `supabase db pull` pour récupérer le schéma actuel de prod
- [ ] `supabase start` lance la base locale (Docker doit tourner)
- [ ] `supabase db reset` applique toutes les migrations en local
- [ ] Studio local sur http://localhost:54323

**Workflow ensuite** : nouvelles migrations → `supabase migration new <nom>` → écrire le SQL → `supabase db reset` (test local) → `supabase db push` (applique en prod). Plus de copier-coller.
